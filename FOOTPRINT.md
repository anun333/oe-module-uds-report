## What installing it changes in the database

22 statements in `sql/install.sql`, every one classified below. Each sits inside an `#If…` guard (`#IfNotTable`, `#IfNotRow2D`, `#IfMissingColumn`, `#IfRow3D`), so re-running the install changes nothing.

- **Core schema change — adds 3 columns to OpenEMR's `patient_data` table:** `uds_housing_status` (VARCHAR(31) NOT NULL DEFAULT ''), `uds_agricultural_worker` (VARCHAR(31) NOT NULL DEFAULT ''), `uds_veteran_status` (VARCHAR(31) NOT NULL DEFAULT '').
- **Tables it creates and owns:** `uds_settings`, `uds_insurance_map`, `uds_quality_run`, `uds_quality_result`, `uds_value_set`, `uds_value_set_code`.
- **Rows added to core tables:** `list_options`, `layout_options`.
  - `list_options`: 21 rows defining 3 new lists: `uds_housing_status`, `uds_agricultural_worker`, `uds_veteran_status`.
  - `layout_options`: 3 fields added to the `DEM` layout (patient Demographics), so every user of that form sees them: Housing Status (UDS) (`uds_housing_status`, group 5), Agricultural Worker (UDS) (`uds_agricultural_worker`, group 5), Military Service (UDS) (`uds_veteran_status`, group 5).
- **Rows it updates in `layout_options`:** only rows it added itself (`uds_veteran_status`, `uds_agricultural_worker`, `uds_housing_status`).

- **No uninstall script** (`sql/` holds only `0_15_0-to-0_15_1_upgrade.sql`, `0_6_0-to-0_7_0_upgrade.sql`, `0_7_2-to-0_8_0_upgrade.sql`, `0_9_0-to-0_10_0_upgrade.sql`, `install.sql`): disabling or removing the module leaves the tables and rows above in place, along with anything staff recorded in them.
