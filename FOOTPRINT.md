## Where it installs

`composer require anun333/oe-module-uds-report` places it in `interface/modules/custom_modules/oe-module-uds-report/` (the `openemr/oe-module-installer-plugin` rule: `custom_modules/` plus the part of the package name after the slash). It changes no OpenEMR core file. Enable it under Modules > Manage Modules.

## What installing it changes in the database

14 statements in `sql/install.sql`, every one classified below. Each sits inside an `#If…` guard (`#IfNotTable`, `#IfMissingColumn`, `#IfNotRow2D`), so re-running the install changes nothing.

- **Core schema change — adds 3 columns to OpenEMR's `patient_data` table:** `uds_housing_status` (VARCHAR(31) NOT NULL DEFAULT ''), `uds_agricultural_worker` (VARCHAR(31) NOT NULL DEFAULT ''), `uds_veteran_status` (VARCHAR(31) NOT NULL DEFAULT '').
- **Tables it creates and owns:** `uds_settings`, `uds_insurance_map`.
- **Rows added to core tables:** `list_options`, `layout_options`.
  - `list_options`: 21 rows defining 3 new lists, all `uds_`-prefixed: `uds_housing_status`, `uds_agricultural_worker`, `uds_veteran_status`.
  - `layout_options`: 3 fields added to the `DEM` layout (patient Demographics), so every user of that form sees them: Housing Status (UDS) (`uds_housing_status`, group 5), Agricultural Worker (UDS) (`uds_agricultural_worker`, group 5), Military Service (UDS) (`uds_veteran_status`, group 5).

- **No uninstall script** (`sql/` holds only `install.sql`): disabling or removing the module leaves these columns, fields, lists and tables in place, along with any data entered in them.
